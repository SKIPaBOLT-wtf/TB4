# RP-031 - AUTO-SNIFF admission validator

Status, dependencies and requirement links: `../manifest.yaml`. [Mandatory work contract](../../../../development/WORK_INSTRUCTION.md) applies, including implementation authorization, per-check evidence and interruption handling. Checkboxes are a manifest projection.

**Deliverable / handoff:** A deterministic parser/admission helper for the common ingress, not the network sniffer.

**Inputs to inspect:** Canonical request schema and existing validation helpers. Historical runtime values are not current facts. New artifacts below are planned, not already implemented.

## Checklist

- [ ] **RP-031.C1** - Validate version, operation type, exact target, payload integrity, authorization, bounds and deadlines before any routing or wake.
- [ ] **RP-031.C2** - Return deterministic reason codes for malformed/unsupported/unknown-target requests, tied to a receipt or ingress revision even when operation_id is unreadable.
- [ ] **RP-031.C3** - Test hostile encodings, duplicate keys/identities, oversized data, stale requests, missing targets and changed payload under a reused identity.
- [ ] **RP-031.C4** - Prove invalid input cannot execute, overwrite a valid receipt or leak submitted sensitive data into status or debug logs.

**Acceptance / records:** All four checks and the common work-contract gates must pass. Store per-check evidence in `../evidence/RP-031/Axxx/` and INTENT/OUTCOME events in `docs/development/journal/RP-031/Axxx/`; update the manifest and RESUME before proceeding.

**Rollback / unresolved action:** Disable new admission and retain bounded rejection evidence; do not pass malformed traffic directly to FETCHER.
