## Compatibility, privacy and rollback
R2 private settings are separate from installed v1 profiles. There is no automatic login, real topology discovery, enrollment or production runtime activation in this standalone unreleased workflow. Trusted installer/commissioning composition supplies already authorized provider adapters and descriptor/release context; RP023/024/025 and later release integration remain separate plan gates. These missing future integrations are visible BLOCKED states, not a fabricated successful setup.

All tests use fresh synthetic private directories/keys and isolated credentials; publication contains no owner paths, host IDs, topology, provider errors or key bytes. Actual Windows token/DACL/handle checks and Linux native permission/no-follow/filesystem/flock checks were executed on their own platforms. Unsupported storage is refused without chmod/ACL repair. No home credential, live provider root, network configuration, installed profile or running role was changed.

Rollback tests restore the preceding protected choices as a new revision only while stopped and with unchanged identity/root/operation/credential history. Binary rollback must keep protected state and external keys intact; no destructive reset or external operation replay is authorized. Sudden power loss, real-domain access/enrollment, ARM64/XFS/ReFS-specific behavior and complete topology/release coverage remain later native/live gates, not inferred from the x64 CI result.
