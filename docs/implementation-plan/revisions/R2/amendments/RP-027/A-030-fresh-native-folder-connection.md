## Per-operation freshness

Only exact NativeFolderProbeProcess joins the proof process allowlist. Normal
NativeFolderAuthorityProcess uses the existing READ/CAS protocol. Pure object
and value pins plus closed VERIFY or READ/CAS validation run before profile or
key IO. The original probe request validator is factored without changing fields.
A duck type, subclass, public dictionary or a saved readiness flag grants nothing.

For each call the actual endpoint then profile native locks cover the protected
selection through one existing fixed transport reply. Pending data is held;
there is no automatic recovery. The complete current pointer and immutable
metadata must still match the connection. The exact operation purpose must be
explicitly selected in the current Setup choices; a broader saved image cannot
supply a hidden scope. Only the just-read protected image restores a fresh existing
purpose-specific native pair, retaining handle, identity, expiry and revocation.
The qualified resolver still opens/rechecks actual native key and known-host files.

Full profile/pending and metadata bytes are checked after the reply. A late change
or reply loss refuses success; CAS remains UNKNOWN and never resends. A later read
can inspect the same effect. Profile, nonce, history, descriptor, image, work and
credential selections are not rewritten. Local UNKNOWN does not block this
transport or first-CAS stale/forced election, and no peer/former-owner ACK exists.
Runtime role/effect authorization remains the caller's independent requirement.
