# RP-027 A-016 - Fresh native current-configuration admission

Ordinary public implementation authority remains unchanged. This completes a
separate local boundary after qualified shared publication and profile promotion;
it does not install, activate or authorize a live deployment.

A typed ConfigurationAdmission consumes the actual protected profile,
NativeCheckpoint, Leadership and the same actual Prerequisites/CommissionedStorage
adapter. Its trusted runtime revision callback rereads these facts on every use:
same fixed authority, coherent current ACTIVE descriptor/configuration/timing and
publication provenance, protected identity/protection, current compatible source,
environment, selected credential capabilities, clock and current role/force state.
A saved SETTINGS_READY/revision or an obsolete transaction's frozen work/WAL
is never a dispatch grant.

Owner-confirmed maintenance release requires the matching ACTIVE transition,
current covered C1 barrier and zero current shared/local blockers. Under the
actual exclusive checkpoint lock it changes only maintenance to null using the
existing full previous/revision/flush/promote/readback frame. Grant, election,
mutation, receipts, operation IDs, work and profile are retained. Ambiguous native
promotion remains inspect-only; recovery freshly qualifies and promotes only the
exact current+1 pending frame whose sole checkpoint change is that release. It
never reconstructs a frame or repeats a remote/root/work action.

Steady-state admission permits legitimate BUSY/UNREAD work and the live runtime's
own durable UNKNOWN receipts. The existing runtime/Effects guards retain their
ordinary action-specific no-replay checks. This boundary neither clears evidence
nor calls a scheduler/executor; every subsequent boundary remains fresh. A stale
or force-superseded local grant refuses ordinary work. Election and heartbeat
remain independent and first-CAS takeover needs no old host/WAL/ACK.

Actual Windows/Linux private-frame cuts, copy/protection failures, late probe
changes, current source/role/credential/storage/clock/capability failures and
ordinary runtime no-replay are required. Default product activation stays closed.
Cloud ACTIVE adoption with the former private host unavailable, Folder/rootless
finalization and full runtime/GUI/helper composition remain separately required.
No check is accepted by this source artifact alone.
