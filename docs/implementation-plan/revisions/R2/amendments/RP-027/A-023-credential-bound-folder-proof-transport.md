## Trusted endpoint and native lifetime

An exact protected ProbeEndpoint pins target/trust, absolute selected executable,
endpoint/port/user, existing private known-host file/native content-identity
version and bounded timeout. This is trusted setup input, never LLM/shared JSON.
Fresh native identity, private permissions and selected versions are checked on
every use. One explicit IdentityFile prevents a missing -i path from selecting
default identities. Config/agent/implicit certificates/alternate auth/prompts/
proxy/control/forwarding/local-command/update/discovery/fallback/retry are closed.
File directives quote the OpenSSH grammar and escape tokens; control/environment
interpolation paths refuse. Current Windows9.5p1 offline policy evidence proves
syntax only, retaining its first failed known-host output comparison.

Linux names the still-held sealed parent-process descriptor, never the original
selected pathname or a temporary key copy. OpenSSH closes inherited descriptors;
the child self-fd/pass_fds hypothesis was rejected before implementation. Procfs
access failure refuses without an alternative path. Windows supplies the native-
confirmed canonical original path while its read-only handle denies write/delete
sharing. Both key and known-host handles recheck before/after the bounded process
and close on every exit. This is a trusted same-account boundary, not a hostile
local-code sandbox; actual authenticated Windows transport is not yet proven.

## Closed purpose and private observation

The exact FolderProbeRunner consumes one thread-owned transient VERIFY slot
bound to spec/root/domain/authority/nonce. CredentialResolver/LocalStore still
return only Outcome; no caller command/payload/secret/proof result is added to
their public API. The exact CredentialProbeProcess arms one private slot, invokes
FOLDER_PROBE once, consumes its matching reply inside trusted proof code and
clears it on every success/denial/unknown/error. Parallel occupants refuse without
replacing the first slot or sending another helper request. Slot locks are not
held during IO and do not invert resolver/store order.

Only exact FixedProcess or this exact proof-only type enters FolderProbe/
RemoteFolderCommissioning. Exact selection/origin/current pins and fresh nonce,
closed fields, revision, blueprint/authority/body/ready marker remain required.
Lost/malformed/stale replies yield closed unavailable/UNKNOWN, without retry/raw
diagnostics. Default authority READ/CAS/helper and activation remain unchanged.

## Qualification and limits

Portable rejection/argument tests, actual native Windows/Linux borrowed lifetime/
private restart/permission/version/expiry/revocation/parallel/unknown tests and
required actual Linux sealed-parent SSH/helper/physical-root/first-run tests must
qualify this source. Synthetic replies cannot qualify authentication or physical
storage; offline -G cannot qualify native borrowed use. Required Linux has no
applicable skips.

This unit does not persist a new endpoint schema, migrate/reselect keys, provide
normal authority READ/CAS, provision a service/root or activate/promote runtime.
Durable protected endpoint reconstruction, explicit authority purposes, complete
runtime/GUI and common/final-source qualification remain separate bounded units.
Original private profile/work/history stays intact; DenyActivation and C1-C4 holds
remain. A source checkpoint alone accepts no check.
