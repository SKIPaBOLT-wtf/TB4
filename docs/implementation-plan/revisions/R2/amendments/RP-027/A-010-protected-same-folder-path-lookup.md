# RP-027 amendment A-010: protected same-folder path lookup

Unreleased engineering continuation of the recorded same-folder design. This
unit prepares immutable lookup facts, without performing a product rename or
accepting any C1-C4 check. Physical relocation, shared effect settlement and final
configuration promotion require their own qualified units.

The actual fresh resolved Maintenance gate, NativeCheckpoint reservation and
Effects authority are required before preparing one protected Linux native
frame. It binds installation/transition/profile revision and hash, source pin,
original root/domain/spec/handle/commissioning marker, source/destination paths,
current private same-filesystem parent identities and existing root/SQLite/journal
identities. All seven protected stores must be distinct and outside both root
trees. No work, authority, profile, role or artifact is changed by this fact write.
An occupied destination or another shared root plan is refused. A native pending
first write remains unavailable until explicit exact current-C1 recovery.

The closed 20-field FOLDER_PATH_MAPPING schema limits metadata to 64 KiB, with
the existing 1 MiB native frame bound. The first frame is immutable: revision one,
no predecessor and exact current protected native binding. Its schema blob uses
explicit LF bytes and is added only to the unreleased compatibility profile.
Released profiles and installed SKILL pointers remain unchanged.

Lookup examines exactly the two pinned paths and current protected parent
identities. It requires one exact original root inode, unchanged protected
SQLite/journal identities and the existing retained canonical commissioning
marker. Missing, occupied conflicting, symlinked, replaced or mutated facts are
refused. It never scans, elects a role, starts a task or grants a physical send.
Existing leadership freshness/CAS governs role takeover independently; former
owner or peer acknowledgements are not lookup inputs.

The ordinary server-local helper accepts an optional protected --mapping-store
pointer alongside its existing private static configuration. Default static
behavior and the exact READ/CAS RPC shape are retained. The pointer never enters
client RPC data. A mapped commissioning read facade delegates to the actual
original FolderCommissioning and preserves the same spec, handle and artifact
seals. It exposes no create/seed/move operation.

Qualification uses an owned real Linux ext4/xfs authority with actual protected
native stores, resolved C1, commissioning/discovery/publication and source pin.
Before/after lookup is tested with an explicitly test-only fixture rename. Tests
must retain the same authority, file identities, seals and used artifact bytes;
exercise the actual helper subprocess and first-run verifier; and refuse changed
owner/profile/source/work/role/clock/capabilities/parents/native store/frame and
ambiguous pending writes. Required targeted Linux CI supports this unit; final
full Windows/Linux/native/Qt/frozen/common gates remain required after all changes.
