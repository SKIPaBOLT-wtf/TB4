# RP-027 amendment A-039 - Own native Main pending recovery

Status: source; actual native/current platform/common C1-C4 qualification required.
This extends A037's separately held original-Main recovery scope, not deployment.

## Exact own pending operation

recover_native_folder_main is a narrow restart entry point for an already
PREPARED own ACTIVE-adoption child. It accepts own original/stage/archive/
transaction/checkpoint stores and installer-owned access/source/clock/capability
inputs. An old in-memory Main connection is unnecessary. Ordinary native Main
connections continue to reject pending data; no general pending-read flag exists.

Before key/transport use, actual distinct native frames must identify the exact
current full parent, pending successor, prepared payload hash, frozen stage and
full original archive. The own endpoint and credential image remain those of
the parent. Native adoption also explicitly rejects an endpoint change in stage.

A private read-only proof context reconstructs the existing native checker and
current leadership from the frozen own stage. It keeps the original Main binding
and private storage request. The existing transaction lock remains held through
fresh source/role/physical/full-profile qualification. The Main lock is taken
after those remote observations, in transaction-before-Main order. The exact
same current and pending bytes are compared before promoting that existing child.
No new frame/save, shared CAS, role acquisition, effect send or replay occurs.

The completed Main remains INCOMPLETE and the existing local reservation/grant,
full previous profile and archive remain. Recovery leaves the prepared journal
for normal inspection; NO_PENDING alone grants no acceptance or activation.
No former installation's files, credential, availability or ACK are required.
Other existing recovery paths and persisted schema/hash meanings are unchanged.

## Qualification

Synthetic actual fixed-SSH cases cover cold restart before/after native promote,
unavailable old in-memory transports, ordinary pending Main denial, exact bytes
without resave or CAS, missing authorization, changed stage/archive/child,
current endpoint/key/source/force loss, a late pending-byte change after proof
and rejected silent stage endpoint replacement. Default/affected regressions,
actual Linux execution and current package/platform/common C1-C4 acceptance
remain separate gates; source and collection counts are not acceptance.
