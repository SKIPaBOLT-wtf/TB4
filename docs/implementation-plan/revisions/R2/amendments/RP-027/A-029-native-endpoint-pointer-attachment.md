# RP-027 amendment A-029 — native endpoint pointer attachment

This links already selected immutable endpoint metadata to an actual protected
Setup profile. It does not create a transport, first-run proof or activation.

## Actual native link

NativeFolderEndpointAttachment accepts only the exact immutable endpoint class
and an actual Windows/Linux private profile at a distinct native binding. Every
use rereads native protection/binding and the endpoint revision1/previous-null
frame. Endpoint then profile is the fixed native lock order, matching prior
endpoint recovery. A pure validated profile-field helper retains the original
endpoint facts; actual native/profile/fresh/nonalias checks still precede it.
An arbitrary dictionary is never a proof.

Explicit owner authorization adds only the closed optional root/ref/binding
pointer to a fresh INCOMPLETE profile with no unresolved local UNKNOWN. All full
parent fields, identity, nonce, image, choices, history and derived data remain;
one revision-checked save retains the complete prior payload. The current exact
same pointer is idempotent, with no state/cache/history reset, even in READY or
UNKNOWN. A different existing pointer is refused; this is not a route replacement
or endpoint migration API. The UNKNOWN guard restricts a new selection change,
never first-CAS stale/forced election or takeover, and no peer/old-owner ACK exists.

## Interruption

Closed inspect reports only UNSELECTED/PENDING/ATTACHED, opaque reference and
metadata_only true, with credential_ready/runtime_active/automatic_replay false.
Restart recovery reads real native current/pending bytes directly; it does not
invent a Setup model to evade pending protection. Only the same existing child
revision with exact full previous parent and pointer-only payload can promote,
after fresh endpoint/profile/selected-handle/revocation checks. Conflicting
revision, parent, pointer, profile, metadata protection or immutable frame stays
held. Recovery does not reconstruct a candidate, repeat save, create metadata,
open a key, send work, reset UNKNOWN or infer rollback from a lost reply.

Actual Windows/Linux tests cover full-parent/key/history preservation and zero
credential-use/key-open/RPC, idempotent READY/UNKNOWN, explicit owner checks,
